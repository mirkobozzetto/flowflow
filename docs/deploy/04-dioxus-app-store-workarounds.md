# Dioxus 0.7 iOS App Store workarounds — full breakdown

This document captures every Apple App Store validation error we hit shipping FlowFlow with `dx 0.7.7` and the exact fix applied. Each fix is now baked into `Makefile` target `appstore` so `make appstore` produces an IPA validated by `xcrun altool --validate-app` with **zero errors, zero warnings**.

Related upstream: [Dioxus issue #3817](https://github.com/DioxusLabs/dioxus/issues/3817) (still open, 2026-05-25).

## Root cause

`dx build --platform ios --device --release` emits an `Info.plist` that is incomplete for App Store distribution. Xcode-built apps get these keys injected automatically by the iOS toolchain; `dx` does not. The IPA packaging step in `make appstore` originally used `ditto -c -k --sequesterRsrc Payload FlowFlow.ipa` which produced an archive without the required `Payload/` top-level directory.

Additionally, the widget extension (declared via `[[ios.widget_extensions]]` in `Dioxus.toml`, PR #4842) emits an Info.plist that lacks `UIRequiredDeviceCapabilities` and several `DT*` keys.

Finally, the icon catalog compilation via `actool` silently degrades when the installed iOS simulator runtime build does not match the iphoneos SDK build version — `Assets.car` is not produced, only flat PNGs.

## Error log + fixes (in order Apple's validator surfaced them)

### Error 1: `The IPA is invalid. It does not include a Payload directory.`

Root cause: `ditto -c -k --sequesterRsrc Payload FlowFlow.ipa` zips the *contents* of `Payload/`, stripping the parent directory.

Fix (in `Makefile`):

```makefile
cd /tmp/flowflow-ipa && zip -qry FlowFlow.ipa Payload -x "*.DS_Store" "__MACOSX*"
```

### Error 2: `Invalid Bundle. UIRequiredDeviceCapabilities arm64 missing on recording-widget.appex`

Root cause: widget Info.plist generated by `dx` for widget extensions lacks `UIRequiredDeviceCapabilities`.

Fix (in `Makefile`, applied to widget):

```sh
plutil -insert UIRequiredDeviceCapabilities -json '["arm64"]' \
  target/dx/flowflow/release/ios/Flowflow.app/PlugIns/recording_widget.appex/Info.plist
```

### Error 3: `Invalid Bundle OS Type code. CFBundlePackageType must be APPL`

Root cause: `dx`-generated main app `Info.plist` does not declare `CFBundlePackageType`. Xcode would inject `APPL` automatically.

Companion fix: same patch also injects `DTPlatformVersion`, `DTPlatformBuild`, `DTSDKName`, `DTSDKBuild`, `DTXcode`, `DTXcodeBuild`, `DTCompiler`, `BuildMachineOSBuild`. Apple does not error on each missing key independently — the validator stops at the first one — but Transporter and post-install checks reference all of them. We populate them in one block reading runtime values from `xcrun` and `defaults`.

Fix (in `Makefile`, dynamic):

```sh
SDK_VERSION=$(xcrun --sdk iphoneos --show-sdk-version)
SDK_BUILD=$(xcrun --sdk iphoneos --show-sdk-build-version)
OS_BUILD=$(sw_vers -buildVersion)
XCODE_DT=$(defaults read /Applications/Xcode.app/Contents/Info DTXcode)
XCODE_DT_BUILD=$(defaults read /Applications/Xcode.app/Contents/Info DTXcodeBuild)

PLIST=target/dx/flowflow/release/ios/Flowflow.app/Info.plist
plutil -replace CFBundlePackageType -string APPL $PLIST
plutil -replace DTPlatformVersion -string $SDK_VERSION $PLIST
plutil -replace DTPlatformBuild -string $SDK_BUILD $PLIST
plutil -replace DTSDKName -string iphoneos$SDK_VERSION $PLIST
plutil -replace DTSDKBuild -string $SDK_BUILD $PLIST
plutil -replace DTXcode -string $XCODE_DT $PLIST
plutil -replace DTXcodeBuild -string $XCODE_DT_BUILD $PLIST
plutil -replace DTCompiler -string com.apple.compilers.llvm.clang.1_0 $PLIST
plutil -replace BuildMachineOSBuild -string $OS_BUILD $PLIST
```

The widget gets the same set plus `LSRequiresIPhoneOS=true` and `CFBundleSupportedPlatforms=["iPhoneOS"]`.

### Error 4: `Missing required icon file. 120x120 icon missing for iPhone iOS >=10.0`

Root cause: `inject-icon.sh` calls `xcrun actool --compile ... --platform iphoneos ...`. With an iOS simulator runtime older than the iphoneos SDK build (e.g. runtime 23E244 vs SDK 23E252), actool fails its internal simulator probe and falls back to writing flat PNGs without `Assets.car`. Apple's validator then sees `CFBundleIconName=AppIcon` (which points at the catalog) but no catalog → reports the 120x120 missing.

Fix: ensure the iOS simulator runtime matches the SDK build:

```sh
xcodebuild -downloadPlatform iOS
```

This downloads the matching runtime. `actool` then emits a proper `Assets.car` containing all icon sizes (120, 152, 167, 180, 1024). `inject-icon.sh` already merges the partial `Info.plist` via `PlistBuddy Merge`, so once `Assets.car` exists, Apple validates cleanly.

Belt-and-suspenders: keep flat PNGs at the bundle root (`AppIcon60x60@2x.png`, `AppIcon60x60@3x.png`, `AppIcon1024x1024.png`) and `Assets.car`. Apple accepts both layouts.

### Warning: `CFBundleShortVersionString mismatch 1.0 vs 1.0.0`

Root cause: `[[ios.widget_extensions]]` block in `Dioxus.toml` and the widget Swift target use different version strings. The main app declares `1.0.0`, the widget defaults to `1.0`.

Fix (in `Makefile`):

```sh
plutil -replace CFBundleShortVersionString -string 1.0.0 \
  target/dx/flowflow/release/ios/Flowflow.app/PlugIns/recording_widget.appex/Info.plist
```

## Local preflight (no upload to Apple)

Once all the above are applied, validate locally with the same tool Apple uses post-upload:

```sh
xcrun altool --validate-app \
  -f /Users/mirkobozzetto/code/flowflow/FlowFlow.ipa \
  -t ios \
  -u mirko@mirko.re \
  -p <app-specific-password>
```

Requires an app-specific password from https://appleid.apple.com → Sign-In and Security → App-Specific Passwords. Revoke after use.

Expected output:

```
VERIFY SUCCEEDED with no errors
No errors validating archive at '.../FlowFlow.ipa'.
```

If you get warnings (like the version mismatch), fix and re-validate. Validation takes ~50 seconds.

## Summary of all fixes baked into `Makefile`

| Fix | Target file | When |
|---|---|---|
| `Payload/` zip wrapper | `Makefile` ditto → zip | always |
| `CFBundlePackageType=APPL` + DT* keys | main `Info.plist` | every `make appstore` |
| `UIRequiredDeviceCapabilities=["arm64"]` | widget `Info.plist` | every `make appstore` |
| Widget version sync `1.0.0` | widget `Info.plist` | every `make appstore` |
| Widget DT* + LSRequiresIPhoneOS + CFBundleSupportedPlatforms | widget `Info.plist` | every `make appstore` |
| Sim runtime matching SDK | one-time | `xcodebuild -downloadPlatform iOS` |

## Reproducing from scratch

1. `xcodebuild -downloadPlatform iOS` (one-time, only if `actool` reports runtime mismatch)
2. Add `APPLE_TEAM_ID=R477R8NK27` to `.env`
3. `make appstore` → produces `FlowFlow.ipa` at repo root
4. Validate locally: `xcrun altool --validate-app -f FlowFlow.ipa -t ios -u mirko@mirko.re -p <app-specific>`
5. Drag IPA into Transporter → `Distribuer`

## What we'd push upstream (Dioxus issue #3817)

The fix in Dioxus CLI would be:

1. `packages/cli/assets/ios/ios.plist.hbs` — add `CFBundlePackageType=APPL` + all `DT*` placeholders populated at build time
2. `packages/cli/src/build/ios_swift.rs` — same for widget extensions
3. `packages/cli/src/build/request.rs` — replace `ditto` IPA packaging with `zip -ry` keeping `Payload/` prefix
4. Bundle command should call `actool` with `--include-all-app-icons` after verifying matching sim runtime; fail loud if mismatch instead of silent degradation
