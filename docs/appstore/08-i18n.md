# 8. Stratégie i18n (Dioxus / Rust)

## Recommandation

**`dioxus-i18n` v0.5.1** + **`sys-locale` v0.3** + **`unic-langid` v0.9**

`dioxus-i18n` est LE standard communautaire pour Dioxus. Maintenu par marc2332 (contributeur core Dioxus). 30k+ downloads. Basé sur Mozilla Project Fluent. Supporte Dioxus ^0.7 (confirmé dans les deps crate 0.5.1).

## Comparaison crates

| Crate | Verdict |
|---|---|
| **dioxus-i18n** | **PICK.** Signal réactif, `t!()` macro RSX-native, `set_language()` → re-render auto. Zero glue. |
| fluent-rs (raw) | Trop low-level. Faudrait rebuilder ce que dioxus-i18n fournit déjà. |
| i18n-embed + cargo-i18n | Plus puissant (checks compile-time) mais setup lourd, pas Dioxus-réactif. Overkill. |
| rust-i18n | Simple `t!()` + YAML, mais plurals limités, pas Dioxus-réactif. |
| gettext-rs | Besoin de binaires système (msgfmt). Mauvais cross-compile iOS. Éviter. |

**Pourquoi Fluent** : la logique pluriel/genre vit dans le fichier `.ftl` (job du traducteur), pas dans Rust. Important pour Dutch/German plus tard.

## Cargo.toml

```toml
dioxus-i18n = "0.5.1"
sys-locale = "0.3"
unic-langid = "0.9"
```

Toutes pure Rust, pas de deps C. Cross-compile iOS safe.

## Détection locale (iOS)

`sys-locale` supporte explicitement iOS (+ watchOS/tvOS/visionOS).
Lit `NSLocale.preferredLanguages` sous le capot.

```rust
fn detect_locale() -> unic_langid::LanguageIdentifier {
    sys_locale::get_locale()
        .and_then(|s| s.parse().ok())
        .unwrap_or(langid!("fr-FR"))
}
```

## Fichiers `.ftl` (Fluent)

Structure : `assets/i18n/{locale}.ftl`

`assets/i18n/fr-FR.ftl` :
```ftl
recordings = Enregistrements
transcribe = Transcrire
delete-note = Supprimer la note
import-doc = Importer un document
global = Global
new-folder = Nouveau dossier
save = Enregistrer
cancel = Annuler
settings = Réglages
notes-count = { $count ->
    [one] { $count } note
   *[other] { $count } notes
}
```

## Initialisation (App root)

Dans `src/ui/mod.rs` :

```rust
use dioxus::prelude::*;
use dioxus_i18n::prelude::*;
use unic_langid::langid;

#[component]
fn App() -> Element {
    use_init_i18n(|| {
        I18nConfig::new(detect_locale())
            .with_locale((
                langid!("fr-FR"),
                include_str!("../../assets/i18n/fr-FR.ftl"),
            ))
            .with_locale((
                langid!("en-US"),
                include_str!("../../assets/i18n/en-US.ftl"),
            ))
            .with_fallback(langid!("fr-FR"))
    });
    rsx!( /* routing existant */ )
}
```

**`include_str!`** obligatoire sur iOS : pas de filesystem runtime pour les fichiers locale dans le bundle app (même contrainte que WASM).

## Usage dans les composants

```rust
use dioxus_i18n::t;

rsx! {
    h1 { { t!("recordings") } }
    button { { t!("transcribe") } }
    span { { t!("notes-count", count: notes.len()) } }
}
```

## Switch de langue (Settings)

```rust
let mut i18n = i18n();
let to_french = move |_| i18n.set_language(langid!("fr-FR"));
let to_english = move |_| i18n.set_language(langid!("en-US"));
```

`set_language()` mute un signal réactif → tous les `t!()` re-render automatiquement.

### Persistence

- Au démarrage : lire `ui_locale` dans SQLite settings_repo. Si absent, `detect_locale()`.
- Au toggle Settings : `set_language()` + écrire dans settings_repo.

## Extraction des strings

Pas d'extracteur automatique pour Rust/RSX. Approche manuelle :

```bash
rg '"[A-ZÉÀÈ]' src/ui/
```

Remplacer chaque string hardcodée par `{ t!("key") }`. ~250 keys, ~4-6h mécanique, composant par composant.

## App Store Connect localization

Deux couches indépendantes :

1. **Binary** = le travail `.ftl` ci-dessus.
2. **App Store Connect** = metadata par langue (nom, description, keywords, screenshots).
   - French metadata → users locale FR + régions FR sans EN.
   - Fallback vers la langue primaire si pas de traduction.
   - Screenshots localisés optionnels (fallback vers next-best langue).
   - Media Manager → pick language → upload par device/langue.
