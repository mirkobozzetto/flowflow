# Definition of Done: RFC 0014 T16 - passkey signup/login web UI + become-admin

> The backend socle (T10/T11a/T11b register+login+logout+WebUser, T13 roles, TA1 bootstrap) is shipped.
> T16 is the browser front that exercises it. Auth is passkey/WebAuthn (Rev 2), NOT email/password.

## Acceptance criteria

| # | Criterion (from spec) | Source | Validated by |
|---|------------------------|--------|--------------|
| C1 | A new user registers a passkey in-browser (email + optional name -> attestation ceremony -> persisted web_user + auto-login session) | RFC T16 / §6.1 | browser: register with a platform authenticator, land logged-in |
| C2 | A returning user logs in by passkey (email -> assertion -> session cookie) | RFC T16 / §6.1 | browser: log in, land on /account |
| C3 | Session persists across reloads AND a cold tab (empty sessionStorage, live cookie) restores identity + csrf via `GET /v1/auth/me` | RFC T16 ("session persists across reloads") | browser: reload + reopen tab, still signed in |
| C4 | Logout clears the session (cookie + sessionStorage) and returns to the auth page | RFC §6.9 | browser: sign out -> back to `/` |
| C5 | A logged-in user clicks "Become admin", enters the ADMIN_TOKEN -> promoted to admin (one-shot), then reaches the dashboard/studio | RFC §6.2 M1 / TA1 | browser: bootstrap, role flips, admin surface unlocks |
| C6 | `/v1/auth/*` is same-origin proxied so the httpOnly `web_session` cookie is first-party (was admin-only) | RFC M14 / TA3 (auth slice) | new proxy route forwards cookie + set-cookie |
| C7 | No new backend auth logic beyond a read-only `GET /v1/auth/me`; ceremonies/session/bootstrap untouched | scope guard | grep: backend diff = me handler + 1 route line only |

## Edit scope (authorized files)

Backend (marketplace-flowflow), minimal companion to the UI:
- `src/web_auth.rs` - add `GET /v1/auth/me` handler (`{web_user_id, email, display_name, role, csrf}`, behind `WebUser`)
- `src/lib.rs` - register `/v1/auth/me`

Frontend (marketplace-flowflow `admin/`):
- `admin/package.json` - add `@simplewebauthn/browser`
- `admin/src/lib/api.ts` - passkey register/login/logout + `getMe` + `becomeAdmin` clients
- `admin/src/routes/v1/auth/$.ts` (NEW) - same-origin proxy for `/v1/auth/*` (mirror the admin proxy)
- `admin/src/routes/index.tsx` - REWRITE: ADMIN_TOKEN paste -> passkey signup/login
- `admin/src/routes/account.tsx` (NEW) - profile + role + logout + "Become admin" (bootstrap)
- `admin/src/routeTree.gen.ts` - regenerated by the TanStack build (not hand-authored)

## Out of scope (named, deferred)

- Role-scoped IA / nuqs / route guards refonte (T40), node canvas (T41), catalogue split (T30)
- Admin "who connected / set role" view (T15), access-requests UI (T22)
- TA4 rate-limit / no-enumeration hardening on `/v1/auth/*` (already noted deferred on the backend)
- Dashboard/studio guards stay as-is (they bail to `/` on missing csrf; deep-link cold-load bounces via `/account`)
- The standalone ADMIN_TOKEN login page is dropped (token is now bootstrap-only per the RFC sunset); the
  backend `/v1/admin/login` still answers pre-bootstrap as a curl break-glass.

## Notable decisions (surfaced)

- WebAuthn browser lib = `@simplewebauthn/browser` ^13 (de-facto standard; pairs with webauthn-rs 0.5 by
  unwrapping `options.publicKey` and posting the response JSON to `/finish`). Hand-rolling base64url +
  credential serialization on a security path is the bug-prone path avoided.
- `GET /v1/auth/me` returns the session `csrf` so a cold load (cookie alive, sessionStorage empty) is
  fully recoverable - the only thing that makes C3 hold for a reopened tab.
- One csrf key (`ff_admin_csrf`) shared with the existing admin client, so dashboard/studio "just work"
  on the passkey admin session post-bootstrap with no change to their api calls.
