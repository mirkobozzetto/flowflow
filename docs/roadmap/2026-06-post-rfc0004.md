### 1.2 Rafraîchissement temps réel après sync (répond à ta question 1)

**Symptôme:** après une sync entrante, les notes sont en base mais l'écran ne
les affiche pas tant qu'on ne quitte/relance pas l'app.

**Cause:** la liste de notes est chargée dans un `Signal` au montage. La sync
écrit directement en SQLite via une AUTRE connexion, en arrière-plan. L'UI
Dioxus n'a aucun moyen de savoir que la base a changé -> pas de re-render.

**Le mécanisme existe déjà à moitié:** `SyncEngine` expose `SyncActivity`
(Idle/Syncing/Done{applied}/Error) et `ui/sync/controls.rs` le poll déjà
toutes les 500 ms. Il manque juste de faire RÉAGIR la liste de notes.

**Solution (à implémenter plus tard, pas maintenant):**
- Quand `SyncActivity` passe à `Done { applied > 0 }` (ou après un
  `reconcile`), incrémenter un `Signal` "data_version" partagé.
- `NotesList`, la sidebar (conversations/dossiers) et `NoteDetail` ouvert
  s'abonnent à ce signal et rechargent leur requête.
- Idéalement aussi pour l'inbound servi (listener), pas que le bouton.

Effort: S (petit). Risque: faible (lecture seule, pas de schéma).

## 2. Sync: sécurité du re-sync + appairage (réponses + suites)

### 2.1 Re-sync, est-ce que ça casse quelque chose ? (réponse à ta question 2)

**Non, le re-sync est sûr et idempotent.** C'est prouvé par les tests
(`notes_flow_both_directions_and_resync_is_idempotent`: la 2e session pousse 0,
applique 0). Pourquoi:

- Chaque appareil ne pousse que ses propres lignes au-dessus du watermark du
  pair. Rien à pousser = rien ne se passe.
- Le merge se fait par version vector: rejouer une ligne déjà appliquée =
  no-op (skip durable).
- Aucune duplication possible (clé = entity_id + version_vector).

**Précautions à prendre quand même:**

1. **Même version des deux côtés** (sinon "protocol version mismatch", refus
   propre, aucun dégât).
2. **Même Wi-Fi** + les deux apps au premier plan (limite iOS: pas de sync en
   arrière-plan).
3. **Pare-feu macOS:** autoriser les connexions entrantes vers Flowflow.app
   (sinon l'iPhone ne peut pas joindre le Mac -> "connection refused").
4. **Backup iPhone avant la toute première sync** (ceinture + bretelles).
   Conceptuellement l'appareil plein ne perd rien (un appareil vide n'a aucun
   tombstone, donc ne peut rien effacer), mais un backup rend tout imprévu
   récupérable.
5. **Ne pas re-coller un vieux code d'appairage:** le code est à usage unique,
   son port meurt dès l'appairage réussi (déjà appairé = ne rien refaire).

### 2.2 Appairage QR (UX, P2)

Aujourd'hui le QR est décoratif: le scheme `flowflow://` n'est pas enregistré,
donc l'app Appareil photo iOS dit "aucune donnée utilisable trouvée". Le chemin
fonctionnel est le copier-coller de l'URI.

À faire (mini-passe dédiée): enregistrer `flowflow://` (CFBundleURLTypes,
injectable post-build comme l'icône) + spike pour vérifier que Dioxus/winit iOS
transmet l'URL d'ouverture -> scan caméra ouvre l'app directement. Fallback si
le spike échoue: scanner QR intégré (AVCaptureSession en FFI).
