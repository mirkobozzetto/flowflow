Drafts - zone Thèmes (sidebar)

Tout est cliquable : teste les micro-animations. Chaque variante vaut pour mobile ET desktop, les différences sont notées. Recommandations encadrées en orange.

Zone 1 - Créer un thème (le bouton +)

Problèmes actuels : le + ne change pas d'état (il faut deviner qu'il referme), l'input apparaît sans transition, le gros bouton check orange est lourd.

A. Accordéon + pivot Reco
Le + pivote en croix, le champ se déplie en accordéon. Enter valide, la croix referme.
Thèmes
Dev
Pro
  • Le + devient une croix orange : l'état ouvert/fermé est lisible d'un coup d'oeil.
  • Check discret intégré au champ, qui ne s'allume que quand le nom est non vide.
  • Même comportement mobile et desktop, zéro surprise.

Coût : faible (CSS + 1 signal). Cohérent avec le chevron-pivot déjà en place.

B. Rangée fantôme
Le + ajoute une rangée pointillée en tête de liste, prête à taper, comme une note brouillon.
Thèmes
Enter ↵
Dev
Pro
  • Le futur thème apparaît exactement là où il vivra : très naturel.
  • Pointillés + icône grisée = état brouillon évident, pas de bouton du tout.
  • Hint "Enter" utile sur desktop, inutile sur mobile (le clavier a sa touche OK).

Coût : faible. Esc ou clic ailleurs annule.

C. Bottom sheet
Mobile : une feuille glisse du bas (pattern iOS). Desktop : la même chose en popover sous le +.
Thèmes
Dev
Pro

Nouveau thème

  • Focus total sur la création, clavier mobile bien géré.
  • Mais : une modale pour taper un seul mot, c'est lourd pour l'usage.
  • Deux patterns différents mobile/desktop = plus de code à maintenir.

Coût : moyen. À garder pour des formulaires plus riches (description, parent).

Zone 2 - Actions sur un thème (les ...)

Problèmes actuels : il faut deviner que ... s'ouvre, les 3 icônes nues apparaissent dessous sans libellé ni hiérarchie, le danger (supprimer) ressemble à renommer.

A. Reveal inline glissant
Les ... pivotent, les actions glissent dans la rangée même, à droite. Pas de saut de layout.
Dev
Pro
  • Compact : tout reste sur une ligne, aucune rangée supplémentaire.
  • Les ... pivotent en vertical orange : l'état ouvert est visible.
  • Le rouge n'apparaît qu'au survol de la corbeille : danger signalé sans crier.
  • Toujours des icônes sans libellé : la devinette reste partielle (tooltips desktop seulement).

Coût : faible.

B. Menu contextuel ancré Reco
Clic sur ... = petit menu avec icône + libellé. Supprimer en rouge, séparé. Zéro devinette.
Dev
Pro
  • Libellés = plus aucune ambiguïté, accessible, élégant (pattern Apple/Linear/Notion).
  • Apparition en scale + fade depuis le coin : micro-animation sobre.
  • Supprimer isolé par un séparateur et en rouge : hiérarchie du danger claire.
  • Marche tel quel sur mobile (assez large pour le doigt) et desktop.

Coût : moyen (positionnement ancré + fermeture au clic extérieur, backdrop déjà existant pour le picker).

C. Hover desktop + swipe mobile
Desktop : les actions apparaissent au survol de la ligne, plus de ... du tout. Mobile : swipe gauche (pattern iOS Mail).

Pro
  • Desktop : zéro chrome au repos, très épuré, découvrable au premier survol.
  • Mobile : swipe natif iOS, libellés sous les icônes, rouge pour supprimer.
  • Mais : le swipe est invisible tant qu'on ne le connaît pas, et le geste est plus coûteux à implémenter en Dioxus (pointer events).
  • Sous-thème ne tient pas dans le swipe : il faudrait le déplacer ailleurs.

Coût : élevé (gestes tactiles). Le hover desktop seul est par contre très bon marché.

Ma combinaison recommandée

Zone 1 : A (accordéon + pivot) partout. Zone 2 : B (menu ancré avec libellés) partout, plus le hover de C en bonus desktop (les ... n'apparaissent qu'au survol de la ligne, le menu reste le même). Le tout réutilise les codes déjà en place : chevron-pivot, backdrop du picker, palette orange/stone. Minimal, lisible, et chaque état a une transition.
